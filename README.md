# GmPan 公司文件资源管理系统

单公司内网文件管理系统，采用 Go、Vue3、Element Plus、MySQL 和本地文件存储。支持公司、部门、个人三个空间，用户名或手机号密码登录、短信验证码登录、分片断点续传、文件备注搜索、已有文件扫描登记、发布审核、回收站和操作日志。

需求和权限规则见 [公司文件资源管理系统需求](docs/公司文件资源管理系统需求.md)，部署、HTTPS、日志和备份恢复见 [系统部署操作手册](docs/系统部署操作手册.md)。原始需求和短信平台文档保留在 `docs` 中；首期范围以新的公司文件需求文档为准。

## 开发与构建

使用 Go 1.26 或更新版本、Node.js 22.12 或更新版本及 MySQL。当前开发验证环境为 Go 1.27.2、Node.js 25.2.1，以及端口 13386 上独立的 MySQL 5.7.40 测试实例；部署建议使用仍受维护的 MySQL 版本。不要连接其他项目的数据库运行初始化命令。

将 `config.example.json` 复制为本地 `config.json` 并配置专用数据库，运行数据库初始化、管理员初始化，再构建前端和后端。Windows 下运行 `scripts/build.ps1`，部署包生成到 `release/GmPan`。前端静态资源嵌入 Go 程序，部署电脑不需要 Node.js 或 Go。

普通 `go test ./...` 运行不依赖数据库的测试。完整集成测试需专用测试实例：`GMPAN_TEST_DSN` 指向 `127.0.0.1:13386` 且数据库名留空；测试自行创建并清理随机 `gmpan_test_` 数据库，覆盖权限、备注搜索、重复导入、源文件保护、分片续传、配额和范围下载。该变量不允许指向其他数据库实例。

## 部署前依赖

真实短信需要项目凭证、登录场景和平台侧配置。病毒检查需要 ClamAV 与有效病毒库；未配置或检查失败时不会开放文件内容。真实历史资料目录在目标部署电脑配置，不在开发电脑上扫描。
