# 短信平台接入文档（外部版）

> 版本：v1.0 ｜ 更新日期：2026-10-02 ｜ 适用于：企业客户短信发送接入

## 1. 接入流程

```
1. 签署接入协议，提交企业信息与使用场景
2. 平台开通账号，发放「项目凭证」：AppKey + AppSecret（另配独立测试项目）
3. 按本文档联调（测试项目额度内调试）
4. 联调通过，平台配置正式模板与额度，切换上线
```

> **AppSecret 是唯一凭证，请妥善保管**：不要写入代码仓库、前端页面或日志。泄露请立即联系平台重置。

## 2. 基础约定

| 项 | 说明 |
|---|---|
| 接口基址 | `https://sms.gmwang.com.cn/api/v1` |
| 请求方式 | POST（Content-Type: `application/json`）/ GET |
| 字符编码 | UTF-8 |
| 响应结构 | `{ "code": 0, "msg": "success", "data": { … } }`；`code=0` 成功，非 0 见错误码表 |
| 限频 | 按项目配置 QPS，超限返回 20006 |
| 幂等 | 发送接口以 `requestId` 幂等：同项目同 requestId 重复请求返回首次结果，**不会重复扣量** |

## 3. 鉴权（HMAC-SHA256）

所有业务接口需携带以下 4 个请求头：

| Header | 说明 |
|---|---|
| `X-Gm-AppKey` | 平台分配的 AppKey |
| `X-Gm-Timestamp` | 秒级时间戳（与服务端偏差 ≤ 300 秒）|
| `X-Gm-Nonce` | 随机串（32 位以内，**5 分钟内不得重复**，建议 UUID）|
| `X-Gm-Sign` | 签名，计算方法见下 |

**签名算法**：

```
rawBody   = 请求原始报文（GET 请求为空字符串）
bodyHash  = SHA256_HEX(rawBody)          // 小写十六进制
plain     = AppKey + "\n" + Timestamp + "\n" + Nonce + "\n" + bodyHash
X-Gm-Sign = HMACSHA256_HEX(AppSecret, plain)   // 小写十六进制
```

要点：`bodyHash` 参与签名的必须是**实际发送的原始报文**——先序列化 JSON，再计算签名，再原样发送（不要重新格式化）。

### 签名示例

**cURL**

```bash
BODY='{"templateKey":"standard_code","mobile":"13800000000","requestId":"req-001","variables":{"code":"884218"}}'
TS=$(date +%s)
NONCE=$(uuidgen)
BODYHASH=$(printf '%s' "$BODY" | openssl dgst -sha256 -hex | awk '{print $2}')
SIGN=$(printf '%s\n%s\n%s\n%s' "$APPKEY" "$TS" "$NONCE" "$BODYHASH" | openssl dgst -sha256 -hmac "$APPSECRET" -hex | awk '{print $2}')

curl -X POST https://sms.gmwang.com.cn/api/v1/sms/send \
  -H "Content-Type: application/json" \
  -H "X-Gm-AppKey: $APPKEY" -H "X-Gm-Timestamp: $TS" \
  -H "X-Gm-Nonce: $NONCE" -H "X-Gm-Sign: $SIGN" \
  -d "$BODY"
```

**PHP**

```php
$ts    = (string)time();
$nonce = md5(uniqid('', true));
$body  = json_encode($payload, JSON_UNESCAPED_UNICODE);
$sign  = hash_hmac('sha256', implode("\n", [$appKey, $ts, $nonce, hash('sha256', $body)]), $appSecret);
// headers: X-Gm-AppKey / X-Gm-Timestamp / X-Gm-Nonce / X-Gm-Sign，body 原样发送 $body
```

**Python**

```python
import hashlib, hmac, time, uuid, json, requests
body = json.dumps(payload, ensure_ascii=False)
ts, nonce = str(int(time.time())), uuid.uuid4().hex
body_hash = hashlib.sha256(body.encode()).hexdigest()
sign = hmac.new(app_secret.encode(),
                f"{app_key}\n{ts}\n{nonce}\n{body_hash}".encode(),
                hashlib.sha256).hexdigest()
headers = {"X-Gm-AppKey": app_key, "X-Gm-Timestamp": ts,
           "X-Gm-Nonce": nonce, "X-Gm-Sign": sign}
resp = requests.post(url, data=body.encode(), headers=headers)
```

**Java**

```java
String bodyHash = DigestUtils.sha256Hex(body);            // commons-codec
String plain = appKey + "\n" + ts + "\n" + nonce + "\n" + bodyHash;
String sign = HmacUtils.hmacSha256Hex(appSecret, plain);  // commons-codec
```

## 4. 接口列表

### 4.1 短信发送 `POST /api/v1/sms/send`

**请求体**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| templateKey | string | 是 | 平台分配的模板标识（如 `standard_code`）|
| mobile | string | 单发必填 | 接收手机号（11 位，1[3-9] 开头）|
| mobiles | string[] | 批量必填 | 号码数组，单批 ≤ 200（批量逐号独立校验与计费）|
| requestId | string | 是 | 幂等键，≤ 64 位，**每次业务动作唯一**（建议：业务单号+序号）|
| variables | object | 是 | 模板变量键值对，以模板定义为准 |

**单发响应 `data`**

```json
{ "message_id": "msg20261001120000xxxx", "status": "PENDING", "idempotent": false, "mobile_masked": "138****0000" }
```

**批量响应 `data`**：`{ "results": [ { 同单发结构 }, … ] }`（逐号返回，部分号码校验失败不影响其它号码受理）

**状态说明**：`PENDING` 排队中 → `SENT` 已提交运营商 → `DELIVERED` 送达 / `FAILED` 失败 / `EXPIRED` 超时（失败自动返还额度）

### 4.2 发送状态查询 `GET /api/v1/sms/status?messageId={message_id}`

**响应 `data`**

```json
{ "message_id": "…", "status": "DELIVERED", "template_key": "…", "fail_code": "", "fail_reason": "", "send_time": "…", "delivered_time": "…" }
```

> 状态查询仅能查到**本项目**的消息；建议发送后 3~5 秒再查询（异步下发）。

### 4.3 余额查询 `GET /api/v1/quota`

**响应 `data`**：`{ "user_id": 1, "quotas": [ { 账本明细,含剩余额度/日限/月限 } ] }`

### 4.4 验证码短信 `POST /api/v1/verify-code/send`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| scene | string | 是 | 业务场景标识（平台分配，如 `login`）|
| mobile | string | 是 | 接收手机号 |

响应 `data` 含平台生成的验证码流水信息（验证码本体不下发接口）。**发送频次与有效期由平台侧控制**（同号冷却，默认 60 秒）。

### 4.5 验证码校验 `POST /api/v1/verify-code/check`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| scene | string | 是 | 与发送时一致 |
| mobile | string | 是 | 手机号 |
| code | string | 是 | 用户输入的验证码 |

校验通过返回 `code=0`；错误/过期返回对应业务错误。**校验成功即失效**。

## 5. 模板与内容规范

1. **模板先行**：所有短信基于平台审核通过的模板发送，`templateKey` 与变量名以平台交付为准
2. **变量规范**：变量名以模板定义为准（字母/下划线开头），值的长度/格式需符合模板变量声明
3. **内容合规**：
   - 禁止发送：欺诈诱导、赌博色情、未经授权的营销骚扰等违规内容
   - **短信内容中出现手机号属于运营商重点审查对象**，未报备会被运营商拦截（扣量不补），确有需要请在模板报备时声明并经平台确认
   - 营销类内容需报备为营销模板并使用专属通道

## 6. 错误码表

| code | 说明 | 处理建议 |
|---|---|---|
| 0 | 成功 | — |
| 10001 | 参数错误 | 按 msg 修正 |
| 10002 | 缺少必填参数 | 按 msg 补齐 |
| 20001 | 签名校验失败 | 检查 AppSecret/签名算法/原始报文一致性 |
| 20002 | 时间戳超窗 | 校准服务器时间 |
| 20003 | nonce 重复 | 每次请求更换随机串 |
| 20004 | 项目已禁用 | 联系平台 |
| 20005 | IP 不在白名单 | 核对出口 IP 或联系平台调整 |
| 20006 | 请求过于频繁 | 降低调用频率/增加重试退避 |
| 30001~30004 | 额度不足/超日限/超月限/无账本 | 联系平台充值或调整限额 |
| 40001/40002 | 模板不存在/已停用 | 核对 templateKey |
| 40003 | 模板未授权给该项目 | 联系平台授权 |
| 40004 | 模板变量校验不通过 | 按模板变量规范修正 variables |
| 40005 | 内容触发合规拦截 | 调整内容；勿夹带未报备的手机号等敏感要素 |
| 40006 | 手机号格式不正确 | 核对号码 |
| 40007 | 号码在黑名单 | 移除该号码 |
| 40008 | 暂无可用发送渠道 | 平台自动延迟重试，无需处理；持续出现联系平台 |
| 40009 | 渠道发送失败 | 平台自动降级换渠道重试 |
| 40010 | 消息不存在 | 核对 messageId 与项目归属 |
| 50000/50001 | 系统繁忙 | 稍后重试 |
