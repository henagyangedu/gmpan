# 系统部署操作手册

本手册用于将 GmPan 部署到公司内网 Windows 电脑。客户端访问内网地址；部署电脑主动通过 HTTPS 访问短信平台，无需公网 IP、端口映射或 frp。数据库、上传文件、历史资料、日志和密钥留在公司内部。

员工和网页后台的日常操作另见[用户操作手册](用户操作手册.md)。本文截图均来自本地虚构演示环境，不能照抄其中的服务器路径、账号或公司标识。首次正式部署前，企业或商业使用应按部署包内 `LICENSE` 和 `SPONSORSHIP.md` 办理授权。

Windows 全新安装也可使用含完整 `payload` 的图形部署测试包：解压后双击 `GmPan安装向导.exe`，按[图形部署测试说明](图形部署测试说明.md)操作。向导安装独立 MySQL 8.4 LTS、ClamAV、超管和自动启动服务；已有非空部署目录、数据库和服务不会覆盖。普通源码构建未包含环境组件时，仍使用下文的手工部署步骤。

## 零 源码构建与部署顺序

已有可信的 GmPan Windows 部署包时，从第一节开始；没有部署包时，在 Windows 构建电脑准备 Git、Go 1.26 或更新版本、Node.js 22.12 或更新版本及 npm。版本要求分别见仓库 `go.mod`、`web/package.json` 和锁定的前端依赖。[Vite 环境要求](https://vite.dev/guide/)

在准备保存源码的位置打开 PowerShell，执行：

```powershell
git clone https://gitee.com/lyhcms/gmpan.git
Set-Location .\gmpan
.\scripts\build.ps1
```

GitHub 源码地址为 `https://github.com/henagyangedu/gmpan.git`，二选一即可。脚本执行前端依赖安装、类型检查、静态资源构建、Go 测试和后端编译，任一步失败会中止。构建电脑需要下载依赖，或事先准备已验证的依赖缓存；不需要把构建环境安装到部署电脑。

构建成功后检查 `release/GmPan`：

| 文件 | 用途 |
| --- | --- |
| `gmpan.exe` | 内嵌前端的服务程序 |
| `config.example.json` | 首次配置模板，不含正式密码 |
| `start.ps1`、`init-admin.ps1`、`install-service.ps1` | 前台运行、初始化超管及注册服务 |
| `SHA256SUMS.txt` | 程序 SHA256，传到目标电脑后核对 |
| `系统部署操作手册.md`、`用户操作手册.md`、`公司文件资源管理系统需求.md` | 离线部署、使用及功能范围文档 |
| `images` | 手册配图，随部署目录一并复制 |
| `LICENSE`、`SPONSORSHIP.md` | 使用许可与授权支持说明 |

可在构建电脑打包整个目录，再复制到内网部署电脑。不要把 `.local`、开发数据库、开发账号、日志或开发配置装入部署包。目标电脑可以没有公网 IP；完全无外网时，ClamAV 病毒库需按公司流程离线更新，短信登录保持关闭。

推荐顺序为：准备程序和文件目录 → 安装独立数据库及 ClamAV → 配置与 HTTPS → 初始化数据库和超管 → 前台启动验收 → 创建员工并扫描资料 → 配置服务账号和防火墙 → 开机自启 → 备份恢复演练。尚未在目标电脑完成的步骤不能仅凭开发环境通过就视为已验收。

## 一 部署目录与依赖

推荐使用专用电脑并设置固定内网 IP，关闭自动休眠。开发电脑与部署电脑是两台不同设备；开发预览账号和测试数据库不得复制到正式环境。

将 `release/GmPan` 中全部文件复制到目标电脑，例如 `D:\GmPan`。该目录包含 `gmpan.exe`、配置示例和启动、管理员初始化、服务安装脚本。前端已打包进程序，目标电脑不需要安装 Go、Node.js、Redis、MinIO 或消息队列。

部署前准备独立的 MySQL 数据库和专用数据盘；启用病毒检查时另需 ClamAV 扫描程序及有效病毒库。建议使用仍受维护的 MySQL LTS 版本；当前代码已在隔离的 MySQL 5.7.40 开发实例上验证，不能据此认为旧版本适合新生产部署。

MySQL 安装和服务初始化可参考[官方 Windows 安装文档](https://dev.mysql.com/doc/refman/8.4/en/windows-installation.html)。目标数据库版本需在实际部署环境验证，本手册不把开发用 5.7 实例当作生产兼容性验收结果。

文件夹规划示例：

| 用途 | 路径示例 | 说明 |
| --- | --- | --- |
| 程序和配置 | `D:\GmPan` | 限管理员和专用服务账号读取 |
| 文件存储和读取 | `E:\公司资料` | 原公司资料原位保留；内部 `.gmpan` 保存上传文件、分片，服务账号可读写 |
| 日志 | `D:\GmPanLogs` | 程序可写，限制员工直接读取 |
| 独立备份 | 另一台设备或独立介质 | 不使用同一块物理硬盘作为唯一备份 |

文件根目录必须与程序、配置、证书和日志分开，不能是磁盘根目录。根目录内 `.gmpan` 为系统保留目录，公开扫描会整目录跳过，勿重命名、删除或把个人资料直接放在根目录其它位置。员工不能通过 SMB 直接访问此根目录，否则可绕过应用权限。

## 二 创建专用数据库

使用数据库管理员工具创建空数据库 `gmpan`，字符集 `utf8mb4`，创建仅能访问该库的账号。不要使用其他业务数据库，也不要将数据库端口向全公司开放。

以下 SQL 中口令仅为占位符，部署时替换为独立强密码：

```sql
CREATE DATABASE gmpan CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'gmpan'@'127.0.0.1' IDENTIFIED BY 'REPLACE_WITH_A_STRONG_PASSWORD';
GRANT ALL PRIVILEGES ON gmpan.* TO 'gmpan'@'127.0.0.1';
```

初始化阶段需要该库的建表权限。初始化完成后，可以将运行账号限制为本库 SELECT、INSERT、UPDATE、DELETE 权限；将来升级有表结构调整时再按升级说明临时恢复所需权限。

## 三 填写部署配置

把 `config.example.json` 复制为 `config.json`。JSON 中 Windows 路径使用正斜杠，或对反斜杠转义。相对路径均相对于配置文件所在目录，而非程序工作目录。

| 配置项 | 设置方法 |
| --- | --- |
| listen | 初始监听地址，例如 `192.168.1.20:8443`；本机开发使用 `127.0.0.1:18080`。后台保存端口后，以数据库中的 `listen_port` 为准；监听 IP 仍来自此项 |
| mysql_dsn | 专用账号连接 `gmpan` 库，保留 `charset=utf8mb4&parseTime=true&loc=Local` |
| storage_root | 文件存储和读取根目录，例如 `E:/公司资料`，先创建并授予服务账号读写权限 |
| log_dir | 日志目录，例如 `D:/GmPanLogs` |
| company_name | 登录页和导航展示的公司名称 |
| tls_cert 与 tls_key | HTTPS 证书和私钥路径 |
| max_file_bytes | 默认 10737418240，即 10 GiB |
| personal_quota_bytes | 新账号默认个人配额；管理员可在页面调整每位员工配额 |
| clamscan_path | `clamscan.exe` 的完整路径；不填写则文件保持待安全检查 |
| clam_database_dir | 病毒库目录；留空使用 ClamAV 默认目录，本地或自定义目录安装时应明确配置 |

可以使用 `GMPAN_DSN` 环境变量覆盖数据库连接。配置文件和环境变量不得提交到代码仓库。修改配置后重启服务。

短信仅在超管后台“站点配置 → 短信配置”中管理，保存后立即生效，无需重启。新安装默认关闭短信登录；部署配置文件与环境变量不再读取短信参数。升级时，已保存在后台数据库中的短信设置继续保留；旧 `config.json` 中的 `sms` 字段会被忽略，请删除旧字段及短信环境变量中的凭证。仅在旧文件中填写、尚未保存到后台的设置，需要由超管在后台重新填写。

下面是配置示例中的部分关键字段，需合并到复制出的完整 `config.json`，不能只保留这些字段。地址和口令均为占位示例：

```json
{
  "listen": "192.168.1.20:8443",
  "mysql_dsn": "gmpan:REPLACE_WITH_A_STRONG_PASSWORD@tcp(127.0.0.1:3306)/gmpan?charset=utf8mb4&parseTime=true&loc=Local",
  "storage_root": "E:/公司资料",
  "log_dir": "D:/GmPanLogs",
  "company_name": "您的公司名称",
  "tls_cert": "./certs/server.crt",
  "tls_key": "./certs/server.key",
  "clamscan_path": "C:/ClamAV/clamscan.exe",
  "clam_database_dir": "C:/ClamAV/database"
}
```

先确认上述目录存在，证书已生成或由公司 CA 提供。保留示例中的文件大小、配额和短信等其他配置；未接入短信时，AppKey、AppSecret、场景留空。可以用 `Get-Content -Raw .\config.json | ConvertFrom-Json | Out-Null` 检查 JSON 格式，但这不验证数据库连接和目录权限。

已有文件、索引或未完成任务时，后台禁止直接更换根目录。迁移按第十五节执行，不要删除索引后盲目重扫。旧版 data_dir、legacy_root 只供兼容升级读取，新部署使用 storage_root。

## 四 配置内网 HTTPS

非本机监听必须配置 HTTPS，防止公司网络中明文传输密码、会话和文件。优先使用公司内部 CA 签发、员工电脑已信任的证书。

也可用程序生成只供本公司使用的自签证书，`host` 中必须填写员工实际访问的域名或 IP：

```powershell
.\gmpan.exe certificate -host 'pan.internal,192.168.1.20' -out '.\certs'
```

将配置指向 `certs/server.crt` 和 `certs/server.key`。通过公司设备管理或管理员手工把公钥证书加入员工电脑信任库；不要把私钥发给员工，不要让员工长期绕过浏览器证书警告。自签证书有效期一年，提前安排更新；证书生成命令不会覆盖现有证书。

若使用域名，由内网 DNS 将其解析到固定内网 IP。系统不需要该地址能从公网访问。

## 五 初始化与首次启动

在部署目录执行：

```powershell
.\gmpan.exe migrate -config '.\config.json'
.\init-admin.ps1 -Username admin
.\start.ps1
```

`migrate` 只为当前配置指向的专用数据库创建本系统表。管理员密码通过交互安全输入后传给程序，不放在命令参数中；密码长度为 10～72 字节。首次管理员创建仅允许空用户表，已有账号后请从人员管理页面新增管理员。

启动后访问配置对应的内网 HTTPS 地址。健康接口为 `/api/health`，应返回 `status=ok`。登录后先创建部门和员工账号、设置部门管理员，并为需要短信登录的员工绑定唯一手机号。账号不开放自行注册。

例如监听 `192.168.1.20:8443` 时，员工访问 `https://192.168.1.20:8443/`，健康地址为 `https://192.168.1.20:8443/api/health`。在已信任服务器证书的客户端可执行 `Invoke-RestMethod 'https://192.168.1.20:8443/api/health'`，不要用跳过证书验证来替代正确配置。根路径能打开不等于健康检查通过；`/healthz` 不是本项目的健康接口。

![登录页示意，正式部署使用自己的账号与站点名称](images/login.jpg)

创建一个普通员工验证公司文件可见，另用其他部门员工验证部门隔离；超管和维护管理员均能查看、管理所有空间文件，部门管理员及普通员工仍按归属隔离。部门树只表示组织层级，父子部门不会自动互相获得文件权限。

## 六 配置病毒检查

病毒检查为可配置功能。超管从“站点配置 → 病毒检查”选择不启用、立即或定时模式，设置保存在数据库并立即生效，不写入 `config.json`。不启用时不执行杀毒及其全文件哈希计算，仍保留上传和下载打包所需的完整性校验。已有站点升级保留立即检查模式。

定时模式按北京时间（UTC+8）执行，默认 22:00—次日 06:00，支持跨午夜；时间段结束或策略变更时，取消当前检查并重新排队，后续从该文件重新开始。关机期间不执行任务。不启用或定时模式允许预览、下载尚未完成检查的文件，页面明确标注“未执行病毒检查”；已发现威胁或检查失败的文件仍被阻止。立即模式要求检查通过后才开放内容。三种模式均不能绕过文件权限和发布审核。

以下 ClamAV 配置供启用立即或定时检查时使用；不启用检查不要求杀毒程序运行。完整图形包仍保留离线组件，初始化会验证组件可用，但关闭检查后不再启动后台杀毒任务。

安装官方 ClamAV Windows 发行版，按其配置说明设置病毒库目录并使用 freshclam 更新病毒库。先在命令行确认 `clamscan.exe` 能扫描一份普通测试文件并正常退出，再填写 `clamscan_path`。

程序只调用检查，不使用删除或搬移感染文件参数。对加密内容、递归或扫描上限触发告警，阻止下载并记录状态。目前调用设置单文件检查上限 2048 MiB、累计扫描上限 4096 MiB、递归 20 层、提取文件数 10000。ClamAV 的单文件检查还受引擎内部限制约束，因此“允许上传 10 GiB”不等于“10 GiB 文件可以通过检查并下载”。超过能力范围的文件不自动放行，需先确定支持大文件的检查方案；不能关闭上限告警冒充已检查。[扫描限制说明](https://docs.clamav.net/manual/Usage/Scanning.html)、[官方命令参数](https://github.com/Cisco-Talos/clamav/blob/main/docs/man/clamscan.1.in)

配置生效后，待检查文件会自动处理。未配置、检查失败、检查期间变更或检测异常的文件均不能下载或预览。管理员可在历史资料导入页面重试其有权访问范围内的失败检查。检测异常文件需按公司规则人工处理；本系统不自动清除病毒或删除磁盘源文件。

部署人员可先准备一份不含业务信息的小文本作为正常测试文件，手工验证安装路径及病毒库，例如：

```powershell
& 'C:\ClamAV\clamscan.exe' '--database=C:\ClamAV\database' 'D:\GmPan\scan-check.txt'
$LASTEXITCODE
```

文件和路径需先按实际情况准备；正常测试文件应得到成功的扫描结果。随后在网页上传同一测试文件，确认能从“待安全检查”转为可下载。当前集成调用的是 `clamscan.exe`，不要仅因安装了 `clamd` 服务就误认为应用已经接入。

对历史资料的其他程序修改可能使检查失效。系统在访问时检查大小和修改时间，发现变化后阻止内容访问并重新排队；对于历史文件应重新扫描资料目录更新索引。不要让员工直接改写上传 objects 目录。

## 七 首次扫描历史资料

确认 `storage_root` 精确指向文件存储和读取目录。除 `.gmpan` 系统专用目录外，新登记资料会向公司所有有效员工公开，不应包含本应私有的资料、数据库备份、密钥或配置。

登录超管或维护管理员账号，进入“公司资料扫描”，核对显示路径后点击“扫描历史资料”。扫描将原目录结构登记到公司空间的“历史资料”下，不改动、复制、搬移或删除磁盘原文件。现有内容默认已发布；文件访问由超管保存的病毒检查策略决定；立即模式须检查通过，不启用或定时模式允许访问未检查文件并明确标注。

页面显示新增、更新、跳过、异常数。正常完成应为“已完成”；“部分完成”需要检查权限、目录重名或无法读取的项目。服务中断后的任务显示“已中断”，重新扫描即可继续登记，已登记项目不会重复创建。

重复扫描保留已编辑的展示名称和备注；新增文件登记，大小或修改时间变化的文件重新检查。完整成功扫描后，缺失源文件会标记不可用而不是删除索引。如果扫描出现无法读取目录等异常，不执行批量缺失标记，以免误判。

扫描跳过符号链接、目录联接、系统回收目录和版本控制目录。多个目录要导入时，请先明确统一资料根目录，不要直接指定整块磁盘根路径。

## 八 文件操作与搜索

上传时可为每个文件填写备注，后续在文件详情中编辑，最长 2000 字符。搜索规则为“文件名或备注包含关键词即命中”，只搜索当前空间内有权访问的内容。普通员工修改公共文件名称或备注后，文件重新进入待审核状态。

上传使用 5 MiB 分片、最多 3 个并发请求。未完成任务保留 48 小时，可从传输列表选择原文件续传；系统核对已上传分片的 SHA256，发现不一致时拒绝拼接。服务器清理过期分片，不删除正式文件。

同一目录不覆盖同名项目，包括仍在回收站的项目。移入回收站和恢复只调整索引，不物理删除源文件；目录包含无权管理的他人内容时需由对应空间管理员处理。回收站内个人文件仍占个人配额。首期不提供清空回收站或永久删除入口，需要释放磁盘时由管理员备份后按单独维护方案操作。

内部链接的接收人必须登录并具有文件权限。浏览器支持的图片、PDF、音视频可预览；HTML、SVG、EXE、压缩包不作为网页执行。首期不提供在线解压、多清晰度转码、文件内容全文搜索或跨文件秒传。

## 九 短信联调

按《短信平台接入文档.md》申请独立测试项目及登录场景，确认验证码有效期和错误次数规则，再由超管在后台“站点配置 → 短信配置”填写真实凭证并启用。部署时无需填写短信参数，不要将短信凭证写进 `config.json`。若平台使用 IP 白名单，应登记公司网络的实际出口公网 IP，而不是部署电脑内网 IP。出口为动态 IP 时先与平台确认处理方式。

服务器需主动访问 `https://sms.gmwang.com.cn/api/v1`，不需要公网回调。签名时间要求偏差不超过 300 秒，因此要校准部署电脑时间。发送请求使用 32 位 Nonce，签名与发送使用同一份 JSON 字节。

系统使用验证码专用发送和校验接口，成功校验后验证码由平台作废。平台返回受理不等于手机已送达。由于专用接口未约定 requestId，网络超时不自动重发，避免重复发送或消耗；界面提示改用密码登录。系统还有账号、手机号和 IP 限频，不向未登记或已停用账号发送登录短信。

真实发送测试前，明确测试手机号、发送条数和使用的测试项目额度；当前开发验收只使用本地模拟服务，没有发送真实短信。

## 十 注册 Windows 服务

手工启动验证成功后，停止前台进程。以管理员身份运行部署目录的 `install-service.ps1`。脚本先注册手动启动的 GmPan 服务和故障重启策略，暂不启动服务，避免专用账号尚未配置时以默认账号运行。

在 Windows 服务管理中为 GmPan 设置专用低权限服务账号。授予其程序、配置和证书私钥读取权，日志目录及文件根目录内部 `.gmpan` 的读写权，原公司资料的读取权，以及 ClamAV 程序和病毒库读取权。首次创建 `.gmpan` 等内部目录也需相应目录权限。不要长期使用默认的 LocalSystem 账号运行；注册脚本与服务的系统权限设置需由部署管理员核实。

具体步骤：打开 Windows“服务”→ GmPan 属性 →“登录”，选定专用账号并由部署管理员配置凭据；在文件夹“属性→安全”中分别配置上述权限。先保留手动启动，使用该账号成功启动、上传、扫描、下载并写日志后，再改为自动启动。不要把管理员自己的交互登录会话或映射盘当作服务账号的运行环境。

仅在防火墙的公司内网配置文件中允许所选端口，来源限定为公司网段，不开放公网转发。服务账号测试读取历史目录成功后，执行：

```powershell
Set-Service GmPan -StartupType Automatic
Start-Service GmPan
Get-Service GmPan
```

数据库可在本机运行，不向员工网段开放数据库端口。若历史资料是网络映射盘，服务账号通常看不到交互用户的盘符，应使用具备授权的 UNC 路径，并单独验证网络可达性与只读权限。

## 十一 日志与故障排查

运行日志写入 `log_dir` 下的 JSONL 文件，按日期和 20 MiB 分卷。数据库 `audit_logs` 保存用户、操作类型、对象编号、结果和时间。密码、短信验证码、AppSecret、会话凭证及完整请求体不写日志。日志目录与数据库需要访问限制和定期归档。

| 现象 | 检查方向 |
| --- | --- |
| 无法打开页面 | 服务状态、监听内网 IP、证书、客户端信任、公司防火墙和休眠状态 |
| 健康接口返回 503 | MySQL 服务、账号权限、数据库连接配置 |
| 运行即退出 | 配置格式、目录权限、是否已有实例连接同一数据库；启动错误见控制台或服务事件 |
| 文件可见但不能下载 | 扫描程序及病毒库、文件检查状态、是否超扫描上限、源文件是否缺失或变更 |
| 历史扫描失败 | 根目录、服务账号读取权限、联接目录或目录内同名项目 |
| 短信未受理 | 项目状态、密钥、场景、额度、出口 IP 白名单、服务器时间、出站 HTTPS |
| 员工退出部门后仍见旧页面 | 刷新页面；所有后端请求会依据当前部门重新鉴权，缓存页面不代表仍可下载 |
| PowerShell 阻止运行脚本 | 按组织脚本签名和执行策略处理，或使用原生命令完成对应步骤；不要为部署全局关闭安全策略 |
| 以服务运行后失败、手工运行正常 | 服务登录账号、目录和私钥权限、用户映射盘、服务账号环境变量，与手工启动环境逐项比对 |
| 向导提示已有 GmPan 服务，但对应程序已删除 | 核对每项服务的可执行文件路径，先判断恢复旧站点还是清理废弃注册记录；按[图形部署测试说明的“部署常见问题”](图形部署测试说明.md#六部署常见问题)处理。清理注册记录不能恢复文件，不要删除仍需保留的数据库或 `.gmpan` |
| 需要卸载或清理旧服务 | 在新版 `GmPan安装向导.exe` 选择“卸载 / 清理旧服务”，核对服务和路径后确认；仅移除选中的服务及对应防火墙规则，保留全部数据。仅有单个向导 exe 也可进入卸载功能，无需完整 payload |
| 修改 config.json 后站点名称或短信配置没变化 | 首次初始化后后台相关设置以数据库保存值为准，超管从“站点配置”修改 |
| ZIP 无法生成 | 批次数量和大小、全部可见文件的检查状态、磁盘阈值、是否已有打包或下载任务 |

## 十二 备份与恢复

首次正式导入前做一次备份，日常按公司可接受的数据损失窗口安排自动备份。数据库和文件必须对应同一个时间点，备份目标要与服务电脑物理独立。索引备份不能代替文件备份。

建议维护窗口停服后执行完整备份：

1. 停止 GmPan，确认没有上传、扫描或资料索引任务继续运行。
2. 使用 MySQL 官方备份工具导出 `gmpan` 全库，包括人员、权限、索引和审核日志；不要只备份 entries 表。
3. 备份 storage_root 整个根目录（包含隐藏的 .gmpan）、受限配置、HTTPS 证书和私钥。病毒库可重新下载，但其位置与配置也应记录。
4. 生成备份清单，记录时间、原路径、数据库版本和文件校验值，再启动服务。

恢复先在隔离电脑演练：创建专用空库并恢复数据库，将上传数据和历史资料恢复至记录的原路径，配置独立内网地址和证书。不要让恢复演练使用正式短信凭证。启动后验证员工登录、三个空间隔离、备注搜索、随机样本下载和文件 SHA256，确认成功后才能替换正式服务。已有索引依赖根目录和内部路径，路径变化必须使用下述目录迁移命令，不能简单修改配置。

## 十三 升级与回退

升级前停服、备份数据库和文件、保留原程序。将新构建包的程序替换到原部署目录，保留正式 config.json、certs、数据目录和历史目录。按对应版本升级说明处理数据库变更后启动，验证健康接口、登录和样本文件。

回退必须同时考虑程序和数据库兼容性；涉及结构变更时从升级前备份恢复，不能仅替换旧程序。正式环境不使用开发电脑的 `.local` 目录和测试配置。

## 十四 站点配置、主题与短信后台

首次部署和旧版升级都需使用当前程序初始化所需表结构。升级前按前文停服备份，用新版程序执行 `gmpan.exe migrate -config config.json`，再启动服务。只对 GmPan 专用数据库执行此命令。

超管登录后进入“站点配置”。维护管理员、部门管理员和普通员工均不能读取或修改站点、短信、Logo 配置。维护管理员不能创建超管、提升自己或其他员工为超管，也不能修改、重置或停用超管账号。

- “站点与目录”可修改公司全称、简称、Logo、默认主题、文件存储和读取目录、剩余空间告警阈值和版权链接；站点部署目录只读显示当前可执行程序所在目录。Logo 支持不超过 2 MB、宽高不超过 1024 像素的 PNG/JPEG，服务端重新编码后保存。Logo 随数据库一起备份。
- 三种主题为“目录工作台（A）”“影像资料库（B）”“清爽协作”。右上角可选择个人主题或“跟随站点默认”，个人选择只保存在该员工当前浏览器中，不改变资源权限。
- 默认底部为“长沙感梦科技有限公司 版权所有”，链接 `https://www.gmkj.cc/`，登录页和登录后的页面均显示。
- 目录填写的是部署服务器上的绝对路径，不是浏览者电脑的路径。先创建目录并授予服务账号权限，后台校验目录存在与路径边界，服务启动时检查内部存储可写；不能使用磁盘根目录，不能与系统数据、日志、配置文件冲突。
- 名称、Logo、版权和短信配置保存后生效；其他已打开的浏览器刷新后显示。目录配置保存后需重启服务，页面同时显示当前生效路径和是否待重启。等待文件根目录切换期间暂停创建上传任务和发起扫描。

超管可点击目录输入框或“变更目录”浏览服务器目录，只有空站点允许直接切换；服务账号需具有目录读取及内部数据目录的写入权限。目录变更并重启后，须手动重新扫描新目录资料。已有文件、索引和任务时继续使用停服迁移流程。

“修改监听端口”独立保存到站点数据库设置，保存时检查端口占用，重启前维持原端口。“重启站点”会等待正在处理的 HTTP 请求、停止并重新启动站点后台任务，再读取已保存的目录和端口；不会重启 MySQL 或操作系统。扫描任务运行时拒绝重启。新端口保存后又被其他程序占用时会拒绝发起重启；运行故障请检查应用日志和实际端口占用。

新图形部署包的防火墙规则限定 GmPan 程序、TCP、同子网及专用/域网络，允许随站点端口切换。原先按固定端口部署的规则需维护人员同步调整。站点重启在进程内完成，低权限服务账号不需要获得 Windows 服务管理或防火墙管理权限。
- 已有上传文件、历史索引、未完成上传或扫描任务时，拦截直接切换文件根目录。迁移使用第十五节命令，保留原文件。

“短信配置”可设置启用开关、接口基址、AppKey、AppSecret 和已开通的登录场景。平台地址默认 `https://sms.gmwang.com.cn/api/v1`，只接受 HTTPS 基址。凭证不通过读取接口返回；输入框留空保留原值，要清除时先关闭短信登录并勾选“清除已保存的 AppKey 和 AppSecret”。保存配置不会发短信；没有正式凭证时保持关闭，使用密码登录。

![短信配置，示例未填写真实凭证且保持关闭](images/admin-sms-settings.jpg)

首次启动将配置文件中的公司、目录和短信配置初始化到专用数据库，后续以管理后台保存的值为准。修改 `config.json` 或环境变量不会覆盖已保存的后台配置。数据库备份包含短信凭证，应按敏感配置限制访问；短信接口日志、审计记录不写入凭证明文。短信平台仍需完成项目开通、场景模板、额度及出口 IP 白名单配置。

## 十五 统一文件目录迁移、权限与容量告警

新版本将“上传目录、读取目录”统一为一个文件根目录。站点部署目录只读显示程序实际位置，修改网页设置不会移动程序。超管与维护管理员可在个人、部门空间选择相应员工或部门，查看、搜索、上传、编辑和回收其文件；普通员工、部门管理员的隔离规则保持生效。

原公司资料按原目录保留。系统上传文件保存在根目录内 `.gmpan/objects/company`、`.gmpan/objects/department/部门ID`、`.gmpan/objects/personal/员工ID`，目录使用系统内部名称，网页显示原名称和逻辑层级；分片在 `.gmpan/chunks`。扫描不登记 `.gmpan`。勿把文件根目录配置为 HTTP 静态目录或向员工开放磁盘共享。

旧版升级或已有数据换盘：

1. 停止服务，备份专用数据库、旧上传目录、原公司资料、配置、日志和证书。新根目录不能与程序、日志、配置、证书冲突。
2. 将新版程序放在正式部署目录，创建目标根目录。可直接选旧版公司资料目录；已有公司资料保持原位，旧上传文件复制进 `.gmpan`。迁往独立新目录时，公司资料与上传文件均复制保留旧副本。
3. 执行 `gmpan.exe unify-storage -config config.json -root "E:/公司资料"`。命令获取与服务相同的数据库锁；服务未停会拒绝。复制前后校验 SHA256，同名不同内容会中止，不覆盖文件。失败时数据库仍使用旧目录，核对原因后可重试。原资料变更时先在旧服务重新扫描，再停服迁移。
4. 成功后数据库中的目录设置、原资料来源映射与上传路径一起提交，保留文件 ID、权限、展示名称、备注、回收站状态和续传分片。同步配置文件使用 storage_root，删除旧 data_dir、legacy_root 字段；已有后台设置以数据库为准。
5. 启动新版，确认站点配置的当前文件目录、部署目录、随机文件下载 SHA256、备注搜索、个人与部门权限，重新扫描应不重复也不公开内部文件。暂不删除旧副本；验收并完成独立备份后由管理员处理。不能用旧版扫描统一根目录，回退需恢复配套数据库和旧目录备份。

容量检查以当前文件根目录所在磁盘、服务账号可用空间为准，默认低于总容量 10% 时提示“文件存储空间不足，需要维护”。超管可在站点配置调整为 1～99%，保存立即生效；已登录页面每分钟更新，重新进入页面立即读取。无法获取容量时提示检查磁盘、网络目录和账号权限。此提示不自动删除文件或阻止上传，个人配额独立计算。

支持上传文件夹并保留相对层级。上传、新建目录可移入回收站，子项目一并处理，之后可恢复。当前删除为软删除，不释放磁盘容量，扫描登记的原文件不删除；容量不足仍需管理员按备份与维护流程处理，不能把回收站操作当作磁盘清理。

## 十六 目录上传、目录 ZIP 下载与图片

页面“上传文件 / 文件夹”内选择“选择文件夹上传”，保留相对层级，每个文件仍可填写备注。目录批次在选择和开始上传时检查：最多 500 个文件、合计 2 GiB、32 层、1000 个文件及目录项目。大目录请拆分选择；单文件普通上传仍按原单文件限制执行。浏览器目录选择不包含空文件夹，上传中断按原文件分片续传；已完成部分不会因后续文件失败而回滚。

目录行、卡片及详情的“下载目录”生成 ZIP，包含所选目录、子目录和当前账号可访问的文件，保留中文名称及空目录。只按系统已登记的逻辑目录和权限打包，不直接压缩物理文件根目录；未扫描登记的磁盘文件不会自动进入 ZIP。其他员工的不可见待审文件不打包；当前账号可见但未检查、检查失败、感染或缺失的文件会使整个打包拒绝，并给出处理提示，不会悄悄生成残缺包。回收站项目不打包。

下载与目录批次采用相同大小、数量和层级上限。服务器一次只处理一个目录打包或下载；占用时提示稍后重试。采用 ZIP Store，不做高 CPU 压缩；视频、图片和压缩包通常也无需重复压缩。生成前检查临时空间，预计生成后会低于站点容量告警阈值则拒绝。

临时 ZIP 放在文件根目录 `.gmpan/downloads`（兼容旧版时为旧 data_dir/downloads），不公开扫描。准备接口需登录与 CSRF；取件链接随机、绑定准备人、五分钟内一次有效。下载前重新校验文件权限、状态与索引，成功、失败或断开后清理临时包，未取件五分钟过期清理；进程中断遗留临时包由下次启动清理。此 ZIP 下载不提供跨请求断点续传，失败需重新生成。日志记录准备和下载动作，不记录凭证或 ZIP 取件码。

JPEG、PNG、GIF、WebP、AVIF、BMP 在浏览器支持且符合站点病毒检查策略时可在线预览，列表提供“预览”，点击图片名称可直接打开，预览窗口可“下载原文件”。图片原格式不改动；下载和预览均执行原空间权限。SVG、HTML 等主动内容不以内嵌页面方式执行，其它浏览器不兼容的格式提供原文件下载。

## 同目录批量操作补充

表格提供勾选框，“移入回收站”直接位于下载旁，不再藏于下拉菜单；卡片同样提供勾选与直接操作。选择仅限当前页，换目录、查询、刷新、切换主题或列表视图后清空，避免误操作。

- 批量移入回收站允许混选文件和目录，所选目录内子项递归处理，原磁盘文件保留。最多选择 500 个直接项目，包含子项合计最多 10000 项。有任意项目无管理权或状态变化时整批拒绝，不发生部分删除；之前已回收的子项保留其原状态。
- 批量下载仅接受同一目录内的文件，生成“批量文件.zip”；最多 500 文件、合计 2 GiB。选中目录或包含不同目录的搜索结果时按钮禁用，服务端也会拒绝。立即模式下选中未检查文件须先完成检查；其他模式允许未检查文件打包，发现威胁、检查失败或源文件不可用仍会阻止打包。
- 不能批量打包多个目录。每个目录行的“下载目录”可独立打包该目录及其子目录，沿用前文 ZIP 限制、权限和清理规则。
